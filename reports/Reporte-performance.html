Prueba de performance de la API de creación de productos

Objetivo: Comprender qué ocurre al enviar 50 y 100 solicitudes de creación de productos por segundo durante un minuto.

Fecha: 2 de noviembre de 2026   |   Herramienta: k6   |   Servicio evaluado: dummyjson.com

Preparación autenticada: el script inició sesión una vez, obtuvo el JWT mediante `POST /auth/login` y lo envió como Bearer token. Cada request creó además un `title` diferente.

Resumen ejecutivo

50 solicitudes por segundo
54,53% fallos

Tiempo medio: 160 ms
Tiempo p95: 165 ms
Solicitudes procesadas: 3.002

100 solicitudes por segundo
76,78% fallos

Tiempo medio: 161 ms
Tiempo p95: 163 ms
Solicitudes procesadas: 5.991

Resultado: no aprobado. El login fue exitoso y los títulos fueron únicos. Sin embargo, el servicio rechazó una proporción alta de solicitudes tanto a 50 como a 100 TPS. El p95 permaneció por debajo de 1 segundo, pero las tasas de error excedieron ampliamente el objetivo.

Conclusiones

  • La generación del JWT y la autenticación funcionaron correctamente.
  • Los títulos de cada request fueron distintos, conforme al requisito de unicidad.
  • La velocidad individual fue aceptable, con tiempos cercanos a 160 ms y p95 cercano a 165 ms.
  • El problema principal fue el rechazo masivo: 54,53% de fallos a 50 TPS y 76,78% a 100 TPS.
  • Estos resultados siguen estando afectados por las restricciones del servicio público DummyJSON y no representan necesariamente la capacidad de una aplicación propia.

Recomendaciones

  1. Para pruebas de aceptación, usar un entorno controlado o una API que permita registrar productos sin límites restrictivos.
  2. Confirmar con negocio el volumen máximo real por hora y por minuto, incluyendo el pico de fechas especiales.
  3. Medir además CPU, memoria, base de datos, cola, errores por código HTTP y autoscaling.
  4. Repetir las pruebas sin el límite externo, y validar qué sucede cuando el sistema comienza a degradarse.
